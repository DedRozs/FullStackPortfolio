# Plans - Development Planning Workflow

Development plans live here. Create a plan before starting any non-trivial feature or fix.

## Workflow

1. Create a plan file in `active/` before writing code
2. Name it: `YYYY-MM-DD-short-description.md` (e.g. `2026-05-30-contact-form.md`)
3. Update the plan as decisions are made during implementation
4. Move the file to `archive/` when the work is merged/deployed

## Plan Template

```markdown
# Plan: [Feature/Fix Title]

**Date:** YYYY-MM-DD
**Status:** In Progress | Complete | Abandoned

## Goal

One or two sentences describing what we are building and why.

## Affected Components

- [Component A] - how it changes
- [Component B] - how it changes

## Implementation Approach

Step-by-step plan for implementation.

## Testing Strategy

What tests will be written and how they will be structured.

## Documentation Updates

Which knowledge-base docs need updating as part of this work.

## Risks and Dependencies

Known risks, blocking tasks, or external dependencies.

## Notes

Running notes captured during implementation.
```
